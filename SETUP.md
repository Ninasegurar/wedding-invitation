# Wedding Site — Setup Guide

Your site is a set of plain HTML/CSS/JS files. No build step, no server required.
Everything editable lives in **one file**: `assets/js/site-data.js`.

## 1. Edit your content

Open `assets/js/site-data.js` in any text editor and fill in:

- Your names, wedding date
- Ceremony & reception venue, address, maps link, times
- Your story (add/remove as many chapters as you like)
- Guestbook connections (Formspree + Supabase — see step 3)
- Livestream embed link (see step 4)

Because guests only ever load the finished pages in a browser, they have no
way to edit this file — only you can, by changing it and re-publishing.

To add photos: drop image files into `assets/img/gallery/` and list their
filenames in the `gallery` array in `site-data.js`.

To change the attire note or page wording, edit the relevant `.html` file
directly (e.g. `details.html`).

## 2. Preview locally (optional)

From a terminal, inside the site folder:

```
python3 -m http.server 8080
```

Then open `http://localhost:8080` in a browser.

## 3. Set up the guestbook

The guestbook needs two free services since this is a static site with no
server of its own:

**Formspree — sends you both an email for every note**
1. Go to https://formspree.io and create a free account.
2. Create a new form. Add both your email addresses as recipients in the
   form's settings (Settings → Emails).
3. Copy the form endpoint (looks like `https://formspree.io/f/abc123xy`).
4. Paste it into `site-data.js` → `guestbook.formspreeEndpoint`.

**Supabase — stores notes so they display publicly on the Guestbook page**
1. Go to https://supabase.com, create a free account and a new project.
2. Once the project is ready, open the SQL Editor and run:

```sql
create table guestbook (
  id bigint generated by default as identity primary key,
  name text not null,
  message text not null,
  created_at timestamp with time zone default now()
);

alter table guestbook enable row level security;

create policy "Public can read guestbook"
  on guestbook for select
  using (true);

create policy "Public can sign guestbook"
  on guestbook for insert
  with check (true);
```

3. Go to Project Settings → API. Copy the **Project URL** and the
   **anon public key**.
4. Paste them into `site-data.js` → `guestbook.supabaseUrl` and
   `guestbook.supabaseAnonKey`.

Until both are configured, the form will simply show a "not connected yet"
placeholder instead of erroring out, so it's safe to publish before you've
set these up.

## 4. Set up the livestream

On the day, go live on YouTube (or Vimeo, Zoom, etc.) and grab the **embed
URL**:

- YouTube: on the video page, click Share → Embed, copy the URL inside
  `src="..."` — it looks like `https://www.youtube.com/embed/VIDEO_ID`.
- Vimeo: similar, looks like `https://player.vimeo.com/video/VIDEO_ID`.

Paste it into `site-data.js` → `livestream.embedUrl`. Also paste a normal
shareable link into `watchPageUrl` so there's a backup button. You can set
these up ahead of time with a scheduled YouTube Premiere/Live link, or add
them the morning of.

## 5. Publish the site & connect your domain

Any static hosting service works. Two easy, free options:

**Netlify**
1. Go to https://app.netlify.com, sign up.
2. Drag the whole site folder onto the Netlify dashboard ("Deploy manually").
3. Once deployed, go to Site settings → Domain management → Add a custom
   domain, and follow the instructions to point your domain's DNS
   (usually an A record or CNAME, provided by your domain registrar) at
   Netlify.

**Vercel**
1. Go to https://vercel.com, sign up.
2. Install the Vercel CLI (`npm i -g vercel`) or use their web dashboard's
   drag-and-drop deploy.
3. In Project Settings → Domains, add your domain and update your DNS
   records as instructed.

**GitHub Pages** (free, good if you're comfortable with GitHub)
1. Create a new GitHub repository and push this folder to it.
2. In the repo's Settings → Pages, enable Pages for the main branch.
3. In Settings → Pages, add your custom domain — GitHub will show you the
   DNS records to add at your registrar.

Whichever you choose, once your domain's DNS points to the host, your
wedding site will be live at your own domain (e.g. `yournames.com`).

## 6. Re-publishing after edits

Whenever you edit `site-data.js` or any `.html` file, just re-upload/redeploy
the folder using the same method as step 5 (drag-and-drop again, `git push`,
or `vercel --prod`, depending on your host). Changes go live within a minute
or two.
